# TR Studio

Tray app that drives the Thermalright Core Vision 360 AIO screen. .NET 8 WinForms with a WebView2 UI (vanilla JS and CSS in `src/TRStudio.App/wwwroot`), rendering in `src/TRStudio.Engine`.

## Commands

- Build: `dotnet build TRStudio.sln`
- Test: `dotnet test tests/TRStudio.Engine.Tests`
- UI preview without the app: `node tools/UiPreview/server.js` (port 4173). It loads `tools/UiPreview/mock.js`; when you add a message between the page and the app, add it to the mock too.
- Installer: `powershell -File tools/BuildInstaller.ps1` (needs Inno Setup 6, `third-party/ffmpeg/ffmpeg.exe`, and PawnIO 2.2.0's signed `PawnIO_setup.exe` plus its GPL-2.0 `COPYING` as `PawnIO-LICENSE.txt` in `third-party/pawnio/`; the script checks the setup's SHA-256 and signature), output in `artifacts/`.
- `third-party/` isn't in git.
- README hero GIF: built from `tools/ReadmeDemo` with the Stageshow skill; its README says how to rebuild it.
- Probes for checking features by hand: `tools/MediaProbe` (what Windows reports as playing), `tools/WeatherProbe <city> <out.jpg>` (live Open-Meteo forecast), `tools/ScreenProbe`, `tools/SensorProbe`, `tools/LightProbe [list | effect seconds] [header=30]` (lists the lighting devices found, built-in and through OpenRGB, and runs a smooth effect on them; it changes the real lights; add `ram` from an administrator terminal to include RGB memory).

## Conventions

- UI styling follows [docs/DESIGN.md](docs/DESIGN.md): use the tokens in `app.css`, keep data on solid panels.
- Record user-facing changes in [CHANGELOG.md](CHANGELOG.md).
- The product name is TR Studio. The code and the program file are named for it (`TRStudio.exe`, the `TRStudio.*` namespaces). Four names from the working title stay, because installed copies depend on them: the data folder `C:\ProgramData\CoreVisionStudio`, the `CoreVisionStudio` startup task, the `CoreVisionStudio.SingleInstance` mutex (the installer waits on it), and the page's host `app.corevision` (the page's saved preferences belong to that address). `CoreVision` in `ScreenDevice` and `ScreenProtocol` is the cooler's own name. The installer's `[InstallDelete]` removes the old `CoreVision.App.exe` on update.
- A sensor that can't be read shows a dash and never raises a warning.
- Windows' media objects only work on the thread that created them: keep `MediaMonitor`'s calls on its own thread.
- TR Studio uses the internet for three things only. The weather sends only the chosen city's coordinates to Open-Meteo. The update check asks GitHub for the latest release of `iamfercatapang/tr-studio` and sends nothing about the PC; it can be turned off in Settings. Crash reports go to Sentry only after the user says yes (`Settings.CrashReports`, null = not asked yet); `CrashReporter` never starts otherwise, and `CrashLog.Scrub` takes the user name, PC name and user folders out of everything sent. The DSN lives in `CrashReporter.Dsn`; empty turns reporting off and hides the switch.
- TR Studio is GPL-2.0-or-later (MIT up to 1.6.2). Code may be ported from OpenRGB (GPL-2.0-or-later; a read-only clone may sit at `E:\LLM\Forking\openrgb-src`): put an SPDX line and a credit naming the OpenRGB files and authors at the top of the file, as in `AuraUsbLightingClient.cs`. Don't add dependencies whose license isn't compatible with GPL-2.0-or-later.
- Lighting has two sources, joined by `CombinedLightingClient`. `AuraUsbLightingClient` drives ASUS Aura USB motherboard controllers itself over HID (`HidDevice`; no driver, no admin). `AsrockUsbLightingClient` drives ASRock Polychrome USB boards the same way; it is behind `LightingSettings.Asrock` (off by default) because it has only run against a fake board, so keep it opt-in until an owner confirms it with `LightProbe list asrock`. It puts the board's red-green swap setting back when the link closes, since the board keeps that setting. `EneRamLightingClient` drives ENE RGB memory over the SMBus (`PawnIoSmBus`: PawnIO's own `PawnIOLib.dll` from Program Files, the embedded modules in `PawnIo/`: `SmbusI801.bin` for Intel, tried first, then `SmbusPIIX4.bin` for AMD on port 0, the order OpenRGB uses; admin needed; only AMD has run on real hardware). It is off unless `LightingSettings.Memory` is on, and with it off lighting never touches the SMBus. Keep it that careful: take the shared `Global\Access_SMBUS.HTP.Method` lock for every transfer, write only to addresses that passed `EneController.IsAt`, never to the memory's data chips (0x50 to 0x57), and leave unknown chips alone. Its colors go out on its own thread, newest frame wins, so the slow bus never holds up the other lights. Everything else comes through OpenRGB's SDK server on this PC (`127.0.0.1:6742`, `OpenRgbLightingClient`), which is looked for in the background so it never stalls the frames, and a device both can drive stays with the built-in driver. Lighting adds no internet use. `Settings.Lighting` is null until the user turns lighting on, and `LightingService` connects to nothing before that. TR Studio doesn't install OpenRGB; it starts an installed copy with `--server --startminimized` (`OpenRgbApp`, a switch on the Lighting page). Turning lighting off, sleeping or quitting leaves the LEDs as they are.
- Graphics cards: `GpuLightingClient` (off unless `LightingSettings.Gpu`) reaches each NVIDIA card's lighting chip over the card's own I2C port through NvAPI (`NvApiI2cBus`, no driver, no admin). A card is driven only when all four PCI ids match an entry in `GpuCatalog` (generated by `tools/GpuCatalogGen` from OpenRGB's detector lines; edit the generator, never `GpuCatalog.g.cs`), at that entry's address, and only after the driver's read-only identity check passes (`<Driver>.Open` gives null otherwise). Never scan addresses on a GPU bus, and never call a driver's `Save` on the user's behalf. Colors go out on the client's own thread, newest frame wins. The GALAX RTX 4070 EX Gamer (10DE:2786 10DE:1875) is not in OpenRGB: its v2 chip answers at 0x50 with identity 02 01 and is confirmed on real hardware; `tools/GpuProbe` lists cards and does read-only identity reads. AMD cards (ADL) and the remaining OpenRGB GPU drivers are not ported yet.
- Lighting is a canvas (`LightCanvas.cs`, 320 x 200; the page's picture of it is rendered at that size too): one effect drawn as a pure function of x, y and time, with each zone of each device placed on it as a box (`LightLayout.cs`) whose LEDs sample the color under them. To add an effect, add an entry to `CanvasEffects.All` with its params; the page builds its controls and tile from that list, and the preview picture and tiles are rendered by the engine (`CanvasEffects.Render`), never in JS. A device listed in `LightingSettings.Devices` as Off or DeviceEffect ignores the canvas. `LightingSettings.All` is read only to migrate settings from before the canvas. A zone can be divided into the parts plugged into it (`LightingSettings.Parts`, `LightParts.Split`): each part is a strip or a ring with its own box, keyed `<zone key>#<n>`, while the device still gets one run of LEDs in the same order; run the devices through `LightParts.Split` before `LightingService.Layout`. The page reads `boxes` for the canvas and `zones` for the hardware. Lighting changes are saved to the settings file a moment late (`_lightingSave`), since drags send many a second.
- SignalRGB's plugin repository (`gitlab.com/signalrgb/signal-plugins`) has no license: take no code, device data or images from it. The lighting-app list in `LightingConflicts` and the part sizes on the Lighting page are our own.
- Effects are pure functions of time and position (`LightEffects` holds the shared color math); keep them that way so they stay testable and in step across devices. Colors blend as straight channel values, which is the even fade on LEDs. `OpenRGB.NET` can't set a built-in effect's brightness, so brightness applies to Color and the smooth effects only.
- The picker, `slider` and `colorField` take a flag for use outside the Editor (no undo step, no theme blending); the Lighting page uses it.
- Help links open only pages under `https://github.com/iamfercatapang/tr-studio/` (issue forms in `.github/ISSUE_TEMPLATE`). The one exception is `https://openrgb.org/`, opened from the Lighting page.
- Updates: `UpdateService` installs only an asset named `TRStudio-<version>-Setup.exe` whose SHA-256 matches the digest GitHub gives for it, and runs it with `/VERYSILENT /UPDATE=1`. The installer waits for the app to quit and starts it again. Bump `<Version>` in `TRStudio.App.csproj` and tag the release `v<version>`, or installed copies won't see it as newer.
- Fan and pump speeds are read-only. Fan control was considered and left out: it needs admin and a kernel driver, and FanControl (Rem0o) already does it. Don't reverse engineer FanControl.
- CPU temperature, clock and power and the motherboard's fans are read through the PawnIO driver (LibreHardwareMonitor 0.9.5+ dropped WinRing0). The installer runs PawnIO's own setup when it's missing (task `pawnio`, on by default); uninstalling TR Studio leaves PawnIO, since other monitoring apps share it. Without it those readings show a dash and Metrics shows a note.
